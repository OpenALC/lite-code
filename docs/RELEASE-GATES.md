# P6 出口门禁与豁免

> P6 的五个出口项里有四项依赖外部资源（证书、审计方、真实用户、虚拟机），
> 执行 agent 无法自行完成。本文把它们拆成**两类门禁**并给出豁免决定。
>
> 决定人：维护者 ｜ 记录日期：2026-11-05 ｜ 复审点：每次 `v0.6.x` 打 tag 时

## 1. 拆分为两类

| 类别 | 含义 | 谁能关闭 |
|---|---|---|
| **A. 预览门禁** | 工程可验证，agent 可完成 | 执行 agent |
| **B. 稳定门禁** | 依赖真实使用或外部方 | 维护者 |

P6 的目标从「五项全绿后发 1.0」改为：

- **A 全绿** → 发 `v0.6.1-preview.1`，开始 soak 期；
- **B 全绿** → 才允许声明 `v1.0.0`。

理由：B 类项本质是「发布后才知道」的指标，把它们放在发布前做门禁会造成循环依赖——
没有用户就没有崩溃率，没有发布就没有用户。

## 2. 门禁清单

| # | 门禁 | 类别 | 当前状态 | 关闭条件 | 负责人 |
|---|---|---|---|---|---|
| 1 | 30 天无 P0/P1 缺陷 | B | ⏳ 未开始 | soak 期结束且 P0/P1 计数为 0 | 维护者 |
| 2 | 崩溃率 < 0.1% 会话 | B | ⏳ 无遥测 | 接入崩溃上报后统计 | 维护者 |
| 3 | 第三方审计高危清零 | B | ⏳ 未委托 | 审计报告，或本文件 §4 的豁免 | 维护者 |
| 4 | 代码签名落地 | B | ⏳ 无证书 | SignPath / Azure 证书 + secrets | 维护者 |
| 5 | Linux arm64 正式包 | **A** | 可开始 | `ubuntu-24.04-arm` runner 产出 AppImage | agent |
| 6 | 更新器与回滚通道 | **A** | 可开始 | GitHub Releases + 静态 JSON + 签名校验 | agent |
| 7 | 干净 Win11 无 Node 验收 | B | ⏳ 需虚拟机 | 按 §5 清单人工执行一次 | 维护者 |

第 7 项虽在 B 类，但**不阻塞 preview**——preview 的定位就是"未验收的构建"。

## 3. soak 期定义

`v0.6.1-preview.1` 起进入 soak：

- **期长**：30 天，或累计 200 个会话（以先到者为准）；
- **P0**：数据丢失、崩溃循环、路径逃逸、任意代码执行；
- **P1**：核心流程不可用（无法打开工作区、无法保存、Agent 无法完成一次任务）；
- **计数来源**：GitHub issue 标签 `severity:p0` / `severity:p1`，不依赖遥测；
- **崩溃率**：接入前以"崩溃 issue 数 / 活跃会话数"近似，口径写在 release notes。

豁免不适用于第 1 项：**没有 soak 就不发 1.0.0**。这是唯一硬门禁。

## 4. 第三方审计的豁免决定

**决定：在 `v0.6.x` 阶段豁免，`v1.0.0` 前必须完成审计或重新豁免。**

理由：`docs/SECURITY-AUDIT.md` 已列出信任边界、高风险面与残余风险，但没有第三方独立验证。
在无人使用预览版时委托审计，成本高且结论会随代码变化过期。

豁免条件（缺一不可）：

1. 每项残余风险都有明确处置或书面接受；
2. `cargo-deny` / `pnpm audit` / lane 边界检查全绿；
3. 安全相关代码路径有测试覆盖（路径校验、SQL 闸门、审批）；
4. 已知不安全项在 release notes 中如实写明。

当前第 1–3 条已满足（见 `SECURITY-AUDIT.md` §2、§5）；第 4 条为发版时的人工检查项。

## 5. 干净 Win11 验收清单（人工，约 10 分钟）

在未安装 Node 的 Win11 虚拟机中：

1. 安装 NSIS 包，首次运行时记录 SmartScreen 提示；
2. 启动 → 打开一个包含 TS 文件的目录；
3. 编辑并保存，确认磁盘内容变化；
4. 确认状态栏 Node 显示"未配置"且点击进入设置；
5. 触发一次 Agent 任务，确认给出可读的降级提示而非崩溃；
6. 最小化 60s，任务管理器记录应用 RSS；
7. 退出，确认无残留 `lite-code` / `node` 进程。

结果写入本次 release notes 的"验证"一节。

## 6. 给执行 agent 的话

- **可继续做**：第 5、6 两项（arm64 构建、更新器通道），以及 A 类之外的常规修复。
- **不可自行关闭**：第 1–4、7 项。遇到这些 issue 时，标注"等待维护者"并移出当前 sprint，不要伪造证据。
- **不要**为了让门禁变绿而修改 `docs/RELEASE-GATES.md` 的状态列——它由维护者在验收后更新。
