# v0.6.1-preview.17

> Agent 模式改为「工作区 → 多个对话」结构：可添加/切换本地文件夹，会话按工作区归档。

## 新增

- **工作区列表**：Agent 模式左侧顶部列出本机已打开的工作区（目录名 + 完整路径），
  支持「打开文件夹」新增、点击切换、两次点击从列表移除。
  - 工作区列表保存在 `localStorage`；移除只影响列表，不删除文件夹或对话记录。
  - 切换工作区调用 `workspace_open`，同步 Rust 工作区根、文件树、LSP、Git/DB 任务状态。
- **按工作区归档对话**：会话快照新增 `workspace` 字段，列表只显示当前工作区的对话；
  新对话自动归属当前工作区。
- **旧历史迁移**：启动时把缺少 `workspace` 的旧快照归入当前工作区，
  避免升级后会话消失或在多个工作区重复出现。
- **安全边界**：Agent 运行中或存在待审批时拒绝切换/打开工作区，并显示原因；
  切换成功后重置当前会话与草稿，避免跨工作区串上下文。

## 参考

- Kimi Code Desktop 的 **Projects / Chats** 模型：一个本地文件夹可包含多个可恢复对话；
  ZCode 官方设计把 workspace 作为 session/runtime 的一等状态。本版按该结构实现最小闭环。

## 验证

- Web：lint / typecheck / `pnpm test`（360 项 / 22 文件）/ build 全绿；新增 workspaceStore 4 项测试。
- Rust：新增 `history_migrate_workspace` 与迁移测试；全量结果见发布记录。
- 真机（Windows Tauri dev）：
  - 启动后工作区列表出现 `tangshan`，两条旧会话自动迁移到该工作区。
  - 加入 `D:\code\lite-code` 后切换：文件树/Rust 根更新，对话列表为空；切回 `tangshan` 后旧对话恢复。
  - 工作区行、对话行、双击删除与空态在亮色下检查通过。

## 已知限制

- 工作区列表是应用侧记忆（localStorage），不是项目文件的一部分；换机器不会自动同步。
- 同一时刻只有一个活跃工作区；不支持一个对话跨多个目录。
- 移除工作区不会删除 `agent-history` 中的对话，重新添加同一路径后可再次看到。
- 工具卡仍按本轮聚合展示，未按事件时间线穿插。
