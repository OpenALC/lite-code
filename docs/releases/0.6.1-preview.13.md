# v0.6.1-preview.13

> Agent 会话补齐模型/思考选择、上下文预算、文本附件与“选中代码加入对话”。

## 新增

- **模型选择**：Agent 头部读取 `providers_load` 中已启用且配置了密钥的供应商模型，
  可在发送首条消息前切换模型；会话建立后选择器锁定，提示“新会话生效”。
- **思考强度**：按所选模型配置的 `thinking` 列表展示挡位（off/low/medium/high/max 等），
  随 `session_create` 透传；`max` 由后端归一到 `high`，`off` 不发送 reasoning 字段。
- **上下文预算**：无会话时也显示所选模型的 `contextK`，例如 `0 / 1000k`，
  并展示压缩阈值刻度；会话建立后改用后端返回的实际预算。
- **新会话**：清空当前消息流并允许重新选择模型/思考；运行中或待审批时禁用。
- **文本附件**：`agent_pick_files` 原生文件选择器，最多 10 个、单文件 256 KiB、
  总量 1 MiB，仅接受 UTF-8 文本；composer 显示文件名/大小 chips，可逐个移除。
  发送时以 `<attachment name path>` 标签注入会话文本，消息流只显示 `[附件: 文件名]`。
- **选中代码加入对话**：编辑器右键菜单新增“添加到 Agent 对话”，把选区以
  `路径:起止行` + 围栏代码块追加到 Agent 草稿；未落盘的演示缓冲区回退到标签标题，
  单个选区超过 20k 字符时截断并标注。

## 行为说明

- 模型与思考挡位作用于**新建会话**；已有会话保持创建时的模型，避免中途换模型导致
  上下文/工具输出不一致。
- 附件由用户显式选择，路径不受工作区限制；二进制或非 UTF-8 文件返回可读错误。
- 供应商配置变化会广播 `providers:changed`，模型下拉即时刷新。

## 验证

- Rust：`cargo test --workspace --locked` 601 项全绿（新增 runtime 模型选择 2 项、
  `reasoning_effort` 映射/拒绝 2 项）。
- Web：`pnpm lint` / `typecheck` / `test`（347 项 / 20 文件）/ `build` 全绿；
  新增 `agentContext` 4 项与 session 模型/附件测试。
- 真机（Windows Tauri dev）：
  - 供应商就绪后模型下拉列出 `deepseek/deepseek-v4.1-flash`、`z-ai/glm-5.3-flash`，
    思考挡位按配置显示 `off/low/high/max`，上下文显示 `0 / 1000k`、阈值 `600k`。
  - 实际发送 `请只回复两个字母：OK`，Agent 返回 `OK`，轮次 `1/25`、
    上下文用量 `1.4k / 1000k`，无错误 banner。
  - `session_create(model=z-ai/glm-5.3-flash, thinking=low)` 返回
    `context_k=1000`、`compress_at_k=600`；未知模型返回 `invalid_argument` 与可操作提示。
  - 在 `main.rs` 演示缓冲区选中代码 → 右键“添加到 Agent 对话” → 右侧 Agent 打开，
    草稿出现 `main.rs:1-8` + `rust` 围栏代码块。
  - 附件 chip 渲染与移除路径通过组件注入验证；原生文件选择器需人工点击验证。

## 修复

- 真机发送曾报 `task not found: <模型 id>`：`sessionCreate` 适配层把模型误传为 `taskId`。
  已在 App 注入处显式转接 `(mode, null, model, thinking)`，并让模式切换保留所选模型。

## 已知问题

  发送会返回 401；请填写服务商实际的 OpenAI-compatible 端点。
- 本次成功对话使用 Command Code 端点；其他供应商端点仍需各自验证。
- Anthropic Messages 传输仍未实现。
- 附件选择器为原生对话框，自动化只能覆盖读取/校验代码路径与 UI 渲染。
