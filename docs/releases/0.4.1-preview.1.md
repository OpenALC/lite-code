# v0.4.1-preview.1

> P4（工作台与并行）里程碑包。Agent 从单一对话变成任务工作台：每个任务有独立
> worktree、变更清单与检查面板，最多 2 个任务并行；后台审批进入状态栏待确认计数。

## 新增

- **Task 实体**：`Planning / Running / Blocked / Review / Done / Failed / Queued`，持久化到数据目录，重启后 `Running` 标记为 `Failed(interrupted)`。
- **worktree 隔离**：数据目录下 `worktrees/<project>/<task>`，分支 `lc/<task>-<slug>`；主工作区保持 clean，worktree 不进入文件树与 watcher。
- **并发队列**：默认 2 个任务运行，第 3 个进入 `Queued`；取消/应用/丢弃后按创建顺序提升。
- **变更与检查**：`git status`/`numstat` 增量扫描、统一 diff、未跟踪文件行数；工作台可查看 diff、应用、丢弃。
- **合并协议**：主工作区必须 clean；基线漂移提示；`--no-ff` 合并；冲突保留 merge 状态与 worktree，解决并提交后再次应用即可收尾。
- **后台审批**：Agent 审批挂起时任务转 `Blocked` 并计入状态栏「N 待确认」；点击跳到对应任务，不抢焦点。
- **工作台标签组**：变更 / 检查 / Diff / 预览按任务记忆并恢复；预览 iframe 在切换时销毁、回到任务时用原 URL 重建。
- **Tauri 命令**：`task_list/create/start/cancel/apply/discard/diff/bind_session`；`session_create` 可绑定任务，在 worktree 内运行 Agent。
- **契约 v0.5**：Task DTO、工作台命令、`task:*` 事件；TS 绑定导出 Task 类型。

## 验证

- 本机 Windows：Rust **321** 项、web **215** 项，合计 **536**；fmt / clippy / lane / cargo-deny / web 四件套全绿。
- 真实临时 git 仓库集成测试：
  - 两个任务并行写不同文件，主工作区 clean；
  - 同一文件不同行并行修改，依次合并两份改动都在；
  - 冲突 → 手动解决/提交 → 再次 apply 收尾为 Done；
  - 仅 `git add` 未提交时 apply 代为提交 merge；
  - 基线漂移计数；冲突未解决时 worktree/diff 不丢。
- 队列：第 3 个任务 Queued，取消后按创建顺序提升。
- 审批联动：NeedsApproval → Blocked + `task:needs_input`；resolve → Running；Final → Review；Error/取消 → Failed。

**未覆盖**：真实 UI 浏览器级点击验收；系统 WebView 独立预览窗口；任务检查 Runner（当前 checks 由上层事件驱动，未内置执行器）。

## 已知问题

1. `ViewTarget` 的 code/web/term/doc 四目标只落地了工作台标签（变更/检查/Diff/预览），独立系统 WebView 预览窗口未实现。
2. 检查面板尚无内置 runner；Agent shell 输出不会自动转成 `TaskCheck`。
3. `tasks.json` 为全局文件，切换 workspace 会按新根重新加载，但旧项目任务仍出现在同一个列表；按项目拆分持久化留待后续。
4. worktree 清理是 best-effort；git 失败时任务字段仍清空，warning 只留在 notes。
5. 安装包未签名；首次运行 SmartScreen 可能提示"未知发布者"。
