# v0.6.1-preview.11

> 预览版：插件系统 v0。左侧活动栏新增「插件」，支持 Node/JavaScript、WASM 命令插件，
> 以及声明式 MCP / LSP 配置。插件代码不进入 Tauri 渲染进程。

## 新增

- **插件管理页**：列表、启用/禁用、重新加载、打开扩展目录、执行插件命令与结果展示；
  顶部命令面板（Ctrl+P）也会列出已启用插件的命令。
- **Node/JS 扩展宿主**：独立 Node 进程，行分隔 JSON-RPC 2.0；插件 `activate(ctx)` 可用
  `commands.register`、`workspace.readFile`（工作区边界校验）、`storage`、`log`。
  单插件失败隔离；插件日志走 stderr，不污染协议；命令默认 120s 超时。
- **WASM 插件**：WASI preview1 command，每次命令独立 worker，无 preopen/网络/宿主环境；
  stdout 必须为单个 JSON；默认超时与 Rust 侧一致；提供 `examples/plugins/hello-wasm`。
- **MCP 插件声明**：`contributes.mcpServers` 合并进 Agent 会话，名称前缀
  `plugin.<pluginId>.<name>`；HTTP/SSE 与无 command 条目跳过。
- **LSP 插件声明**：`contributes.languageServers` 启动 stdio 语言服务器；
  `initialize`/`didOpen`/`didChange`/`didClose`/`publishDiagnostics` 已接入，
  诊断通过 `lsp:diagnostics` 事件显示为 Monaco markers；补全/hover 等后续。
- **清单与安全**：`~/.lite-code/extensions`；项目级插件默认忽略
  （`LC_EXT_ALLOW_PROJECT=1` 开启）；256 KiB 清单上限；main 路径 canonicalize 必须落在
  插件目录内；Node/LSP 子进程清理 provider 密钥环境变量；WASM 无文件/网络权限。

## 已知问题

1. Node 插件是可信代码（与 VS Code 相同）；`permissions` 只是安装提示，不是沙箱。
2. WASM 使用 Node `node:wasi` 实验 API，默认无文件/网络；长任务受 120s 限制。
3. LSP v0 只做诊断与全量文本同步；补全、hover、跳转、格式化、代码操作未实现；
   未用真实 typescript-language-server / rust-analyzer 端到端验证。
4. 未实现插件市场、签名、自动更新、Webview UI、树视图、延迟激活与 VS Code API 兼容。
5. 插件级 Agent 工具（直接注册到 Agent 工具表）尚未实现；工具型扩展请用 MCP 声明。
6. Windows 安装包未签名；更新器清单 `signed:false`。
