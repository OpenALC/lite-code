# v0.6.1-preview.56

**日期**：2026-11-09
**类型**：pre-release
**对应里程碑**：P6 稳定化（鸿蒙会话回收与 DNS 预算）

### 亮点

- 鸿蒙宿主会话表回收（上限 32，running 绝不回收，迟到事件 no-op）与
  DNS 解析 800ms 预算化——慢 DNS 不再拖出预探预算，直接回退 stub。

### 变更

- `crates/lc-ohos` 会话回收：
  - `MAX_SESSIONS = 32`（`init_with_factory_and_limit` 可覆盖，下限 1）；
    `SessionHandle` 增加 `created` 序号与共享 `alive` 标记。
  - `create_session` 后在同一把 sessions 锁内回收：按创建序精确回收
    `len - max` 个 `running == false` 的最老会话；取消中的 worker 持有
    running，不会被回收。
  - `RunningGuard` 移至 worker 闭包，`running=false` 即「该会话不会再有事件」；
    `agent_send` 改用锁内 `begin_turn`（查表 + CAS running 原子化）。
  - 迟到事件安全：`TurnEmitter::event` 与 `session_state` 增加 alive 检查，
    回收后任何推送为 no-op；对已回收 ID 发送返回 `NotFound`（客户端需重新
    `session_create`，属预期行为变化）。
- DNS 预算化：`resolve_bounded`——IP 字面量直接解析（零线程）；域名解析进
  单个分离线程 + `recv_timeout`，与 TCP 探测共享 800ms deadline。DNS 超时/
  失败现按「不可达」直接回退 stub（旧行为要等 ureq 5s）。
- 单测 19 → 23 项：回收驱逐序/running 保留、迟到事件丢弃、慢 DNS 预算约束、
  IP 字面量旁路解析。

### 已知问题

| 问题 | 影响 | 规避方式 |
|---|---|---|
| 超时 DNS 线程为分离线程，黑洞 DNS 下每次探测遗留一个线程 | 线程数缓慢增长 | 后续可平台 resolver 或常驻解析 worker |
