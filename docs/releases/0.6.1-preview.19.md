# v0.6.1-preview.19

> 核心不变，移植 Kimi Code Desktop 的高频 Agent 功能：排队发送、对话管理、上下文详情、消息复制。

## 新增

- **排队发送**：运行中或审批挂起时发送消息会进入本地队列，本轮 `done` 后按序自动发送。
  - 队列显示在 composer 上方，可单条移除或清空；附件也可先排队。
  - 新建会话期间的排队不会被首个会话提交覆盖（已补回归测试）。
  - 当前实现是前端队列，不修改 Rust 运行时；不支持在当前轮中途 steer。
- **对话重命名 / 归档**：
  - 线程行悬停出现重命名、归档、删除；重命名为内联输入（Enter 保存，Esc 取消）。
  - 归档对话进入可折叠「已归档」区，可恢复或删除。
  - 对应 Tauri 命令 `history_rename` / `history_archive`，沿用本地快照文件；
    后续轮次保存会保留自定义标题与归档状态（`titleLocked` + 元数据合并）。
- **上下文详情浮层**：点击 composer 下方上下文条，查看已用/预算/压缩阈值、
  最近请求输入输出、缓存 token、累计每轮输入输出。
- **消息复制**：助手消息悬停出现「复制」，使用 `execCommand` 回退实现，
  避免 WebView2 弹出剪贴板权限条。

## 参考

- Kimi Code Desktop：queue/steer 的 composer 交互、线程菜单（重命名/归档/恢复）、
  context popover 与消息操作。

## 验证

- Web：lint / typecheck / `pnpm test`（364 项 / 22 文件）/ build 全绿；
  新增排队（3 项）与建会话期间排队回归测试。
- Rust：历史 rename/archive 与元数据保留单测，桌面测试增至 98 项；全量结果见发布记录。
- 真机（Windows Tauri dev）：
  - 连续发送两条：第一条运行中第二条显示“排队 1 条”，完成后自动发送并产生第二轮用量。
  - 重命名、归档、恢复后列表状态正确；`history_list` 元数据同步。
  - 上下文浮层显示 `1.7k / 1000k`、阈值 `600k`、最近请求与累计用量。
  - 复制按钮点击后显示“已复制”，未再触发剪贴板权限条。

## 已知限制

- 排队是前端顺序队列；不支持 steer（把消息插入当前轮）、编辑重发或按轮回滚。
- 归档只影响历史列表，不删除会话文件；重命名只修改快照标题。
- 工具卡仍按本轮聚合展示，未按事件时间线穿插。
