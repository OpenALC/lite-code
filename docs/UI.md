# UI 设计与风格

## 1. 布局

```
┌──┬────────────────────────────┬──────────────────┐
│活│  标签页                     │                  │
│动│  ┌──────────────────────┐  │   Agent 面板      │
│栏│  │  Monaco              │  │   ─────────────   │
│  │  └──────────────────────┘  │   会话 / 工具调用  │
│  ├────────────────────────────┤   权限确认        │
│  │  终端 | 输出 | 问题         │   上下文用量      │
├──┴────────────────────────────┴──────────────────┤
│ 状态栏：分支 · Node · MCP · 会话 · 内存             │
└──────────────────────────────────────────────────┘
```

**Agent 面板是一等公民，不是侧边栏里的附属标签。** 这是产品区别于普通 IDE 的地方，布局必须体现：常驻右侧、可折叠、宽度可拖；窗口窄时自动收为图标，不挤压编辑器。

用 `dockview-vue` 实现可停靠：拖拽、浮动、布局保存到工作区状态。

## 2. 视觉基调

**高密度、低装饰、工具感。** 参考 Zed 与 Linear 的克制，而非 VS Code 的默认观感。

| 维度 | 定调 |
|---|---|
| 色彩 | 深色默认。背景 `#17181c`，面板 `#1d1f24`，边框 `#2a2d34`（1px 低对比） |
| 强调色 | 单一色相，建议暖橙 `#e8875a`。**避开 VS Code 蓝**，让截图一眼可辨 |
| 明度层级 | 最多四级，靠背景明度而非阴影区分 |
| 效果 | **不用玻璃拟态、不用 backdrop-filter**——WebView 里每层模糊都是 GPU 成本，与"轻量"直接冲突 |
| 字号 | UI 13px / 行高 1.5；代码 13px / 行高 1.6 |
| 字体 | UI `system-ui` 栈；代码 JetBrains Mono → `ui-monospace` 回退 |
| 间距 | 4px 基准，常用 4 / 8 / 12 / 16。面板内边距 12，列表项高 26 |
| 圆角 | 6px（面板）/ 4px（控件），不做全圆角 |
| 动效 | 仅 120–160ms 的透明度与位移。**不做弹窗缩放、不做页面转场**。尊重 `prefers-reduced-motion` |
| 图标 | 单一线型图标集（Lucide），1.5px 描边，不用彩色图标 |
| 滚动条 | 6px、半透明、悬停加深，全局统一 |

## 3. 关键组件

### 文件树

- git 状态用**文字颜色**（M 黄 / A 绿 / D 红 / U 灰）+ 右侧 2px 色条，不用彩色图标
- 目录展开 80ms 淡入，列表虚拟化
- 按需加载，一次一层
- 右键菜单：在终端打开、复制路径、在资源管理器显示

### Agent 会话

- 消息流：用户右对齐窄栏，助手全宽
- **工具调用是卡片**，不是一行文字：显示工具名、参数摘要、耗时、结果前 5 行，可展开全文
- 权限确认以**内联卡片**出现在会话流中（不用模态框），显示完整命令与目标路径，按钮为 `允许 / 本次会话允许同类 / 拒绝`
- 上下文用量以细进度条常驻面板底部，超过 80% 变色
- 压缩事件留一条可展开的"已压缩 N 条消息"记录，**不静默**

### 输入区（Composer）

输入框下方是一排**常驻控件**，四个维度都在这里，不放设置页：

```
┌─────────────────────────────────────────────┐
│ 描述你要做的事…                              │
├─────────────────────────────────────────────┤
│ [自主行动 ▾] [gpt-5 ▾] [思考 中 ▾]      [↑] │
│ 上下文 ████████████░░░░░░░░ 78.4k / 400k    │
└─────────────────────────────────────────────┘
```

**模式选择器**（`[自主行动 ▾]`）——四种模式，每个带一行说明，并给不同的图标与颜色标识：

| 模式 | 标识 | 提示 |
|---|---|---|
| 计划模式 | 虚线边框 | 只读探查，产出计划，不改文件 |
| 仅对话 | 灰色 | 不调用任何工具 |
| 自主行动 | 默认 | 高风险操作会先询问你 |
| 完全自主 | 橙色描边 + 警告图标 | 除黑名单外自动执行 |

`完全自主` 必须有视觉警示——橙色描边加一个不可忽略的图标，因为它是一个"降低安全等级"的选择。切换该模式时弹一次确认（仅首次每会话）。

**思考强度**（`[思考 中 ▾]`）——挡位来自当前模型的能力声明。不支持的挡位置灰，而非隐藏，让用户知道"这个模型没有高挡位"。

**上下文用量**——不是数字，是一条带**阈值刻度**的条：

```
上下文 ████████████░░░░│░░░░░ 78.4k / 400k
                      ↑ 压缩阈值 300k
```

刻度线标出 `compressAtK`，用户能预判"还有多远要压缩"。跨过阈值时条变成黄色，压缩发生后变回橙色并短暂闪烁一次。

**默认模型**在 UI 上与当前会话模型分开显示，用于压缩与风险判定。设置页里必须标注它的用途，避免被误当成兜底模型。

### 供应商面板

左侧栏的第二个一等面板（与资源管理器同级，通过活动栏切换），不是设置页里的子页面。

```
供应商
─────────────────────────────
● OpenAI            responses   [⋯]
  gpt-5        400k / 压缩 300k
  gpt-5-mini   128k / 压缩  96k
● 本地中转           responses   [⋯]
  llama-70b    128k / 压缩  96k
─────────────────────────────
默认模型  gpt-5-mini  (压缩/判定)
[ + 添加供应商 ]
```

模型行展示五要素，两行布局：

| 位置 | 内容 |
|---|---|
| 主行 | 显示 id（可编辑，本地名） |
| 副行 | `上下文 400k / 压缩 300k` |
| 展开后 | 实际 id、思考挡位、端点、启用开关、删除 |

**显示 id 与实际 id 并列展示**——展开时实际 id 用等宽字体灰色显示，与显示 id 形成对照。这是让用户理解"我改的名字不影响请求"的直接方式。

危险操作（删除被会话引用的模型）禁用并给出原因，不做成点了才报错的交互。

### 模型参数的来源标记

每个可编辑参数（上下文窗口、压缩阈值、思考挡位）旁边有一个**极小的来源标记**，三种状态：

| 标记 | 含义 | 视觉 |
|---|---|---|
| `推测` | 来自内置映射表，可能过期 | 虚线下划线，灰 |
| `探测` | 来自 `/models` 端点的返回 | 无下划线，灰 |
| `手动` | 用户改过，永不自动覆盖 | 无标记，正常色 |

编辑任一字段，标记立即变 `手动` 并持久化。内置表更新、点 `[刷新]` 重新探测，都**不会改动已手动设置的值**。

`contextK` 为空时该模型不可启用——上下文窗口是预算计算的前提，不能猜。面板上直接禁用开关并提示原因，不做成启用后才报错。

「刷新全部」并发探测各供应商的 `/models`，结果只用于补全**未被手动覆盖**的字段，并在面板顶部用一行小字汇报：`3 个供应商已更新 · 1 个未响应`。

### 子代理配置

子代理是供应商面板的第二个分组（在模型列表下方），因为它同样属于"模型与能力配置"，而不是会话设置。

```
子代理
─────────────────────────────
 代码探查        gpt-5-mini · 思考低 · 只读
 批量修改        gpt-5 · 思考高 · 自主
[ + 添加子代理 ]
```

每行显示四要素：名称、模型、思考强度、模式。展开后编辑：

| 字段 | 控件 |
|---|---|
| 名称 | 文本 |
| 模型 | 下拉，来自当前启用的模型 |
| 思考强度 | 下拉，受所选模型能力约束 |
| 模式 | 下拉，**不提供「完全自主」以外的提权** |
| 最大轮次 | 数字，默认 12 |
| 系统提示词 | 多行文本 |

**子代理的模式选择器里不含「完全自主」的确认流程**——因为它继承主会话的黑名单，且审批卡冒泡到主会话。UI 上在模式旁标注一行小字："黑名单始终生效"。

会话运行时，子代理在消息流里是**可展开的块**，标题行显示 `代码探查 · gpt-5-mini · 低 · 3/12 轮`，展开后是该子代理的消息与工具调用。默认折叠，避免主会话被淹没。

### 全局默认模式

设置页有一项「新会话默认模式」，默认 `自主行动`。会话内的选择覆盖它，且会话级选择随会话持久化，重开该会话时恢复。

### 命令面板（`Ctrl/Cmd+K`）

所有功能都可触达。这是 power user 的第一入口，也是可发现性的兜底。支持前缀过滤（`>` 命令、`@` 文件、`#` 符号）。

### 状态栏

| 项 | 表现 |
|---|---|
| 分支 | 分支名 + 领先/落后 |
| Node | 绿 `Node 22.4` / 黄 `Node 20.11` / 灰 `未配置`，点击进设置 |
| MCP | 已连接 server 数，异常时变红并可点开详情 |
| 会话 | 运行中会话数 |
| 内存 | 当前 RSS，仅在开发构建显示 |

## 4. i18n

从第一天做，`zh-CN` / `en` 两份 JSON catalog，`vue-i18n`。事后补 i18n 的成本是事前的五倍。

约定：

- 所有用户可见文案走 key，不硬编码
- 错误消息 = 可读描述 + 建议动作，不暴露内部错误码（错误码放 tooltip / 日志）
- 不拼接句子片段（语序在不同语言中不同）

## 5. 可访问性

- 所有交互元素有可见 focus ring
- 对比度达 WCAG AA
- 全应用键盘可达，无鼠标也能完成核心流程
- 动效遵循 `prefers-reduced-motion`

## 6. 性能约定

- **不在主线程做重计算**。搜索排序、diff 计算、语法遍历在 Rust 侧或 Worker 里
- Monaco 动态加载，首屏不含编辑器代码
- 列表全部虚拟化（文件树、搜索结果、会话消息、DB 结果）
- 图片与图标用 SVG symbol，不用字体图标（避免 FOIT）

## 7. 要避免的

- **不做"又一个 VS Code 皮肤"**。差异化在 Agent 的一等公民地位和可感知的轻量（启动快、切换快、最小化后几乎不占资源），不在主题配色
- 不用模态框打断 Agent 流程，审批内联
- 不在 UI 上展示"AI 正在思考"这类无信息量的占位超过 200ms——用真实进度（正在读文件 / 正在执行命令）
- 不做过场动画、不做骨架屏闪烁

## 8. 组件库策略

不引入完整 UI 组件库（Element Plus / Naive 之类会带来 200KB+ 与主题定制成本）。自建最小集：

| 层 | 内容 |
|---|---|
| token | CSS 变量：颜色、间距、字号、圆角、动效时长 |
| primitive | Button / Input / Select / Tooltip / Popover / Dialog / Menu |
| composite | Tree / Tabs / SplitPane / CommandPalette / Toast |

`src/services/` 下**禁止 import 任何框架 API**，只暴露纯函数与 `subscribe()`。这让将来换框架只重写视图层。
